# 宇宙社会模拟游戏总实施计划 V1

## 0. 文档地位

本文件是项目唯一的执行级总计划。需求与世界观仍以以下文档为依据：

- `world_simulation_requirements_v1.md`：模拟系统需求
- `cultivation_gameplay_bible_v1.md`：修炼与玩法总纲
- `current_era_world_bible_2289_v1.md`：2289 年当前时代
- `universe_history_and_social_evolution_v1.md`：历史与社会演化
- `social_response_crime_and_relationships_v1.md`：社会响应、犯罪与关系

其他 `day*`、`stage*`、`phase*` 文件只保留为历史参考，不再作为可直接复制的代码规范。

实际领取任务和执行顺序以 `execution_backlog_v1.md` 为准；本文件定义范围和阶段，不再兼任每日任务队列。

## 1. 五层计划结构

| 层级 | 含义 | 示例 |
|---|---|---|
| L0 总纲 | 游戏最终要成为怎样的系统 | 自主运行且因果一致的开放宇宙 |
| L1 里程碑 | 一组具有独立验收门槛的能力 | M1 一致性内核 |
| L2 系统域 | 里程碑中的主要技术领域 | 承诺与存在性 |
| L3 工作包 | 可连续实施和独立验收的交付物 | M1-WP03 承诺驱动位置 |
| L4 原子步骤 | 明确到文件、动作、结果和证据 | 增加查询接口并构造冲突场景 |
| L5 实施卡 | 精确到类型、API、算法、错误处理和断言 | `M1-IC03 Presence 时间线重建` |

L4 仍然回答“按什么顺序做”，L5 才回答“代码具体怎么实现”。代码级实施卡索引：

- `implementation_cards_m0_m1_v1.md`：编译基线与一致性内核
- `implementation_cards_m2_m4_v1.md`：生活、社会与规模化
- `implementation_cards_m5_m9_v1.md`：交通、星际、修炼、文明与宇宙

状态只允许使用：

- `NOT-STARTED`：尚未开始
- `CODED-UNVERIFIED`：已写源码，但未通过目标 UE 环境验证
- `IN-PROGRESS`：正在实施
- `BLOCKED`：依赖未满足
- `DONE`：产物和验收证据都存在

## 2. L0 项目总纲

### G01 世界自主运行

玩家不参与时，人物、组织、地区、文明和危机仍根据资源、责任、关系、情报与历史行动。任务不是静态清单，而是世界真实需求经过机会编译器筛选后的入口。

### G02 单源真相与有限认知

实际发生的事件只写入事实层；新闻、对话、谣言和玩家记忆属于认知层。任何人都不能无来源地知道远方事实，旧消息可以被新证据纠正，但历史消息本身不能被抹除。

### G03 因果驱动人物

吃饭来自饥饿与食物可得性，上班来自责任与经济压力，犯罪来自冲突、机会和决策，旅行来自目的、票务、路线和时间。随机性只能改变同样合理的候选结果，不能替代原因。

### G04 多精度模拟

玩家附近使用人物、物品和动作细节；远方使用家庭、组织和人口聚合；被玩家认识的重要人物保留稀疏历史。禁止让全宇宙个体运行逐帧状态机。

### G05 一致性优先于画面

人物不能同时出现在两个地点，不能在死亡后继续活动，不能在参战期间回家上班，物品与金钱不能无来源产生。画面只展示模拟状态，不拥有真相。

### G06 可玩而非纯模拟器

系统持续把身体、身份、关系、组织、危机和修炼条件转化为少量可理解机会。所有能力必须能用键鼠或手柄明确操作，世界模拟必须给玩家带来选择与后果。

### G07 可持续工程

每个里程碑必须在目标 UE 版本编译、具有调试查询、可保存、可复现，并有性能预算。实验性 UE 功能不能持有规范数据。

## 3. 全局完成定义

一个工作包只有同时满足以下条件才能标记 `DONE`：

1. 对应数据结构和 API 已写入当前工程。
2. Unreal Header Tool 与 Development Editor 编译通过。
3. Blueprint 或自动场景能够触发主要路径。
4. 至少覆盖成功、拒绝、冲突和大时间跳跃中的适用场景。
5. 结果可通过调试快照或事实日志观察。
6. 不破坏真相、认知、存在性和资源守恒。
7. 文档记录输入、输出、限制和后续扩展点。

## 4. 总体依赖链

`M0 编译基线 -> M1 一致性内核 -> M2 单人生活 -> M3 局部社会 -> M4 长期规模 -> M5 行星交通 -> M6 星际层 -> M7 修炼玩法 -> M8 文明危机 -> M9 宇宙与画面`

M7 的动作原型可在 M4 后与 M5 并行，但正式接入世界结果必须等待 M5。M9 的视觉实验可以提前单独进行，但不能成为模拟系统依赖。

# M0 UE 5.8 编译与可观测基线

## M0-A 工程和工具链

### M0-WP01 Windows 工具链安装与项目生成

状态：`BLOCKED`，等待 Windows 电脑。

依赖：UE 5.8、Visual Studio 2022、C++ 游戏开发工作负载、Windows SDK。

实施步骤：

1. 从 Epic Games Launcher 安装最新 UE 5.8 补丁版并记录完整版本号。
2. 安装 Visual Studio 的 MSVC、Windows SDK、Unreal Visual Studio Tools。
3. 拉取仓库并确认 `.uproject` 的 `EngineAssociation` 为 `5.8`。
4. 右键 `.uproject` 生成 Visual Studio 项目文件。
5. 选择 `Development Editor`、`Win64` 构建 `WorldSimDemoEditor`。
6. 将第一个 UHT、编译或链接错误作为唯一修复目标，禁止同时扩展功能。
7. 循环编译直至编辑器目标成功。

产物：可生成的 `.sln` 与成功的 Editor 构建。

验收证据：完整构建退出码为 0，UE 5.8 能打开项目。

### M0-WP02 源码契约静态清理

状态：`IN-PROGRESS`。

实施步骤：

1. 检查每个 `UCLASS/USTRUCT/UENUM` 的 generated include 顺序。
2. 检查 Blueprint 函数是否使用 UHT 支持的容器和引用类型。
3. 检查所有声明与实现的 const、参数和返回类型一致。
4. 检查不存在字段、重复 include、失效 UE 5.4 配置和空指针解引用。
5. 将编译前能确认的问题一次性修正，不假装替代真实编译。

产物：UE 5.8 编译候选源码。

验收证据：静态契约脚本通过；最终证据仍由 M0-WP01 提供。

# M1 一致性内核

## M1-A 时间、活动与承诺

### M1-WP01 确定性时间调度

状态：`CODED-UNVERIFIED`。

实施步骤：

1. 定义同一分钟内事件优先级：结束、伤亡、位置、开始、需求、决策、消息。
2. 将大时间跳跃拆分到下一关键时间点，而不是所有系统只看最终时刻。
3. 维护稳定排序键：时间、事件类别、主体 ID、事件 ID。
4. 处理零时长、过期、跨越多个活动和连续承诺。
5. 对一次推进 1 分钟与一次推进 1440 分钟比较最终规范状态。

产物：可复现的调度顺序。

验收证据：等量分步推进与整段推进结果一致。

### M1-WP02 活动中断与恢复

状态：`NOT-STARTED`。

实施步骤：

1. 给活动增加开始时间、结束时间、状态和中断原因。
2. 硬承诺开始时检查现有活动，不只过滤新机会。
3. 根据活动类型决定取消、暂停、失败或提前结算。
4. 返还未消耗容量或记录不可退费用。
5. 写入中断事实并触发迟到、违约或健康后果。
6. 禁止同一人物同时存在两个排他活动。

产物：完整活动生命周期。

验收证据：正在吃饭的人遇到紧急撤离时不会继续吃到活动自然结束。

## M1-B 存在性与生命状态

### M1-WP03 承诺驱动 Presence 区间

状态：`PARTIAL`，执行时按 `IN-PROGRESS` 处理。

实施步骤：

1. 明确 `Present/InTransit/Absent/Deceased` 的查询语义。
2. 创建旅行承诺时预留互不重叠的位置区间。
3. 出发时关闭起点 Present 区间并创建 InTransit 区间。
4. 到达时创建目的地 Present 区间。
5. 延误、取消、失踪和死亡时重写未来区间并保留历史区间。
6. LocalPersonManager 实例化前必须通过 Presence 查询。
7. 增加双重地点冲突检测和事实告警。

产物：规范位置时间线。

验收证据：任意人物在任意时刻最多有一个允许出现的位置状态。

### M1-WP04 伤病、失踪、死亡与恢复

状态：`CODED-UNVERIFIED`。

实施步骤：

1. 将生命状态与健康数值分离，死亡不可由普通治疗恢复。
2. 受伤产生医疗需求、工作中断和恢复承诺。
3. 失踪停止普通活动，但允许搜救和调查事件继续引用人物。
4. 确认死亡后关闭未来活动、承诺和 Presence。
5. 未确认死亡只能发布失踪消息，不能生成遗产结算。
6. 找回失踪者时发布纠正事实和新消息。

产物：不可穿帮的生命状态链。

验收证据：死亡、失踪、受伤和获救四条场景均可回放。

## M1-C 真相与认知

### M1-WP05 事实事件规范

状态：`PARTIAL`。

实施步骤：

1. 为事件增加来源实体、因果事件、承诺和可见性标签。
2. 建立事件类型注册表，禁止依赖任意字符串拼写。
3. 定义不可变字段与允许追加的调查结论。
4. 提供按主体、区域、类型、时间和因果链查询。
5. 保证重复执行同一结算不会写入重复事实。

产物：可追溯事实图。

验收证据：任一重要现状能沿事件引用找到来源。

### M1-WP06 消息传播与知识纠正

状态：`PARTIAL`。

实施步骤：

1. 区分公共广播、定向消息、亲眼观察和传闻。
2. 消息记录来源、发布时间、到达时间、可信度和引用事实。
3. 人物接触媒介后才创建知识记录。
4. 多来源消息合并时保留历史并更新相信程度。
5. 新证据通过纠正消息改变认知，不修改旧消息。
6. 玩家 UI 只读取玩家知识，不直接读取事实层。

产物：有限且可纠正的认知系统。

验收证据：未看新闻的玩家不知道远方死亡，看过失踪报道后仍不能断言死亡。

# M2 单人单城市生活切片

## M2-A 身份与出生

### M2-WP01 玩家身份创建

状态：`NOT-STARTED`。

实施步骤：

1. 定义姓名、性别、年龄、外观种子、国籍/辖区、家庭、教育、职业和资产字段。
2. 把捏脸参数作为外观数据，不混入社会身份。
3. 根据背景模板生成合法组合并允许玩家调整。
4. 校验年龄、职业、家庭和居住资格约束。
5. 创建 PersonLite、因果状态、关系和初始知识。

产物：可持久化玩家身份。

验收证据：同一身份种子产生一致背景，非法组合有明确拒绝原因。

### M2-WP02 因果出生点

状态：`NOT-STARTED`。

实施步骤：

1. 为住宅、宿舍、飞船和临时住所定义可出生位置提供者。
2. 按家庭住所、职业班次、当前承诺和时间筛选位置。
3. 检查访问权限、容量、Presence 与关卡可用性。
4. 从合法候选中确定出生区域和具体 SpawnPoint。
5. 无合法位置时生成可解释的临时安置方案。

产物：身份驱动出生服务。

验收证据：维修工、失业居民和在途旅客出生在不同且合理的位置。

## M2-B 一天的生活

### M2-WP03 需求与资源提供者

状态：`PARTIAL`。

实施步骤：

1. 为家庭、餐厅、单位、医院和休闲设施建立机会提供者接口。
2. 从营业时间、库存、容量、价格和权限生成机会。
3. 消耗服务时同步扣除库存、容量和金钱。
4. 设施关闭或缺货时提供替代机会而不是静态任务失败。
5. 将食物、医疗和休息效果由具体产品数据决定。

产物：城市生活服务网络。

验收证据：饿了不等于必然吃到饭，选择受距离、价格和供应影响。

### M2-WP04 工作与日程闭环

状态：`PARTIAL`。

实施步骤：

1. 把工作合同转换为周期性硬/软承诺。
2. 班次开始前生成通勤和准备机会。
3. 到岗后创建工作活动并按完成度结算收入。
4. 迟到、缺勤、请假和事故写入事实并影响雇佣关系。
5. 休息日不生成普通班次，但可生成加班或临时任务。
6. 父母压力、债务和职业目标只改变决策权重，不直接强制行动。

产物：有原因和后果的上班循环。

验收证据：正常上班、迟到、旷工、请假四种路径均自然结算。

### M2-WP05 单日调试验收

状态：`NOT-STARTED`。

实施步骤：

1. 创建一个家庭、单位、餐厅、诊所和交通节点。
2. 创建玩家和至少十名 NPC。
3. 模拟起床、进食、通勤、工作、社交、回家和睡眠。
4. 玩家主动打乱一天并观察 NPC 与单位反应。
5. 对比逐分钟与关键事件跳时结果。
6. 保存、重载并核对人物位置、金钱、承诺和知识。

产物：第一个完整可玩系统切片。

验收证据：连续两天无人物穿帮、重复工资或无来源消息。

# M3 局部社会、关系、组织与执法

## M3-A 关系和组织

### M3-WP01 关系图

状态：`NOT-STARTED`。

实施步骤：

1. 定义亲密、信任、吸引、依赖、尊敬、恐惧、嫉妒、怨恨和亏欠。
2. 关系边只为实际有关联的人创建。
3. 事实事件通过规则改变关系维度并保留原因引用。
4. 请求、帮助、拒绝、背叛和和解生成承诺或消息。
5. 关系影响候选评分，但不直接强制犯罪或爱情。

产物：稀疏可解释关系图。

验收证据：任一关系变化可指出导致它的事件。

### M3-WP02 组织、岗位与权限

状态：`NOT-STARTED`。

实施步骤：

1. 定义组织、部门、岗位、成员、资产、预算和权限。
2. 单位根据服务需求和预算发布岗位及任务。
3. 人物加入组织后获得责任、工资、地点访问和信息渠道。
4. 组织缺员、亏损或危机时自主调整招聘与行动。
5. 组织决定写入事实和可解释决策轨迹。

产物：可运行的小型单位模型。

验收证据：玩家不参与时单位仍能排班、招聘和处理缺勤。

## M3-B 感知、犯罪与案件

### M3-WP03 感知与证据

状态：`NOT-STARTED`。

实施步骤：

1. 行为产生可见、可听、设备、物理和数字痕迹。
2. 目击者按距离、视线、注意力和恐惧形成观察记录。
3. 摄像头和传感器按覆盖、权限和故障状态记录。
4. 证据记录来源、时间、地点、完整性和保管链。
5. 未被感知的行为不能直接触发社会全知响应。

产物：感知到证据的链路。

验收证据：公开犯罪与隐蔽犯罪产生不同报警和调查过程。
